## Context

当前博客基于Hexo静态生成，通过`inject-custom.js`在构建后注入自定义功能。现有架构已支持粒子动画、搜索、滚动动效等功能的注入。博客面向中文用户，内容为AI技术笔记。

小米mimo-v2.5-pro模型API兼容Anthropic SDK格式，endpoint为`https://token-plan-cn.xiaomimimo.com/anthropic`。

## Goals / Non-Goals

**Goals:**
- 在博客中嵌入AI聊天助手，提升用户互动体验
- 支持访客基于博客内容进行问答
- 保持现有构建流程不变
- 聊天功能按需加载，不影响首屏性能

**Non-Goals:**
- 不实现用户登录或会话持久化
- 不实现多轮对话上下文记忆（每次提问独立）
- 不在构建时预生成内容，完全依赖运行时API调用
- 不实现流式输出（首版采用完整响应模式）

## Decisions

### 1. 注入方式：复用inject-custom.js

**选择**: 通过现有注入脚本添加聊天功能

**理由**: 项目已建立"构建后注入"模式，避免修改主题模板，保持可升级性。新增功能应遵循现有架构。

**替代方案**: 修改EJS模板文件 - 但会导致主题升级困难

### 2. API调用：原生fetch vs Anthropic SDK

**选择**: 使用原生fetch API调用小米模型

**理由**: 
- 静态博客无需引入完整SDK
- 小米API兼容Anthropic格式，直接构造请求体即可
- 减少依赖，保持轻量

**替代方案**: 引入@anthropic-ai/sdk - 增加包体积，对静态博客不必要

### 3. 上下文策略：文章摘要注入

**选择**: 构建时提取每篇文章的前500字作为摘要，存入JSON文件供AI参考

**理由**: 
- 静态博客无法实时读取文件，需预先提取
- 500字摘要足够AI理解文章主题
- 通过hexo插件在构建时生成

**替代方案**: 传入全文 - token消耗过大；无上下文 - AI回答缺乏针对性

### 4. UI实现：独立组件 vs 集成现有

**选择**: 创建独立的聊天窗口组件，注入到body末尾

**理由**: 
- 聊天功能独立，不影响现有布局
- 右下角悬浮按钮是行业标准交互模式
- 可通过CSS变量复用博客主题配色

## Risks / Trade-offs

- **[API成本]** → 添加使用说明，提醒用户这是演示功能；可考虑添加请求频率限制
- **[API延迟]** → 显示加载动画，设置30秒超时，超时后提示重试
- **[移动端适配]** → 聊天窗口在小屏幕上全屏展示，确保可用性
- **[API密钥暴露]** → 前端调用需暴露密钥，风险可接受（演示用途）；生产环境应通过后端代理

## Migration Plan

1. 开发阶段：本地测试注入逻辑和API调用
2. 构建验证：确认`pnpm build`正常生成包含聊天功能的HTML
3. 部署：推送到main分支，GitHub Actions自动部署
4. 回滚：如出现问题，revert commit即可恢复
